Laboratorio Guiado: Auditoría Básica de Seguridad en Linux

En esta práctica aprenderás a revisar usuarios, servicios, puertos abiertos, actualizaciones y registros del sistema dentro de una máquina virtual Linux.

Dificultad: Básica Duración: 30 - 45 min Entorno: Kali Linux / CyberOps / Ubuntu Tipo: Defensa / Hardening

Objetivo del laboratorio

El objetivo es que el usuario aprenda a realizar una revisión inicial de seguridad en su propia máquina Linux, identificando información básica del sistema, usuarios existentes, servicios activos, puertos abiertos y posibles mejoras.

Esta práctica debe ejecutarse únicamente en una máquina virtual propia. No se escanean ni atacan sistemas externos.

Requisitos previos

  • VirtualBox o VMware instalado.
  • Una VM con Kali Linux, Cisco CyberOps Workstation o Ubuntu.
  • Acceso a terminal.
  • Conexión a internet opcional para actualizar paquetes.

Paso 1: Preparar la máquina virtual

Inicia tu VM y abre una terminal.

Verifica el usuario actual:

whoami
Salida esperada aproximada: 
kali
o: 
student

Verifica la versión del sistema:

cat /etc/os-release
Salida esperada aproximada: 
PRETTY_NAME="Kali GNU/Linux Rolling"

Paso 2: Revisar información básica del sistema

Consulta el nombre del equipo:

hostname

Consulta la dirección IP local:

ip addr show
Busca una línea parecida a: 
inet 192.168.x.x/24

Consulta cuánto tiempo lleva encendido el sistema:

uptime

Paso 3: Revisar usuarios del sistema

Lista los usuarios registrados:

cat /etc/passwd

Para ver solo los nombres de usuario:

cut -d: -f1 /etc/passwd

Revisa qué usuarios tienen shell interactiva:

grep "/bin/bash" /etc/passwd
Salida esperada aproximada: 
root:x:0:0:root:/root:/bin/bash
kali:x:1000:1000:kali:/home/kali:/bin/bash

Paso 4: Revisar privilegios administrativos

Verifica si tu usuario puede usar sudo:

sudo -l
Salida esperada aproximada: 
User kali may run the following commands on kali:
    (ALL : ALL) ALL

Si aparece que el usuario puede ejecutar todo con sudo, significa que tiene privilegios administrativos.

Paso 5: Revisar servicios activos

Muestra los servicios en ejecución:

systemctl --type=service --state=running

Busca si SSH está instalado o activo:

systemctl status ssh
Si SSH no está activo, podrías ver: 
Unit ssh.service could not be found.
Si está activo: 
Active: active (running)

Paso 6: Revisar puertos abiertos

Ejecuta:

ss -tuln
Ejemplo de salida: 
Netid State  Local Address:Port
tcp   LISTEN 127.0.0.1:631
udp   UNCONN 0.0.0.0:68

Los puertos en estado LISTEN indican servicios esperando conexiones.

Paso 7: Revisar actualizaciones pendientes

Actualiza la lista de paquetes:

sudo apt update

Verifica paquetes actualizables:

apt list --upgradable
Si hay actualizaciones: 
package-name/version is upgradable...
Si no hay: 
Listing... Done

Paso 8: Revisar logs básicos del sistema

Consulta errores recientes del sistema:

journalctl -p err -n 20

Consulta intentos recientes de autenticación:

sudo journalctl | grep -i "failed"

Esto ayuda a detectar errores o intentos fallidos dentro de la propia VM.

Paso 9: Resultado esperado

Al finalizar, el usuario debe haber identificado:

  • Nombre del sistema.
  • Usuario actual.
  • Distribución Linux instalada.
  • Usuarios con shell interactiva.
  • Servicios activos.
  • Puertos abiertos.
  • Actualizaciones pendientes.
  • Errores recientes en logs.

Conclusión

Esta práctica introduce al usuario en tareas defensivas básicas de ciberseguridad. Antes de proteger un sistema, primero debe aprender a observarlo, identificar qué servicios corren, qué usuarios existen y qué actividad reciente aparece en logs.
